Module 1: Exploratory Data Analysis (EDA) & Sensor Data Anatomy

1.1 What is EDA and Why Does It Matter?

Definition

Exploratory Data Analysis (EDA) is the process of investigating a dataset to understand its main characteristics, discover patterns, spot anomalies, test hypotheses, and check assumptions — before building any models. It is the "diagnostic phase" of machine learning.

Why EDA is Critical for This Project
  • Sensor Data is Noisy: Smartphone accelerometers/gyroscopes pick up vibrations, hand tremors, and sensor drift. EDA tells us if the data is clean or needs denoising.
  • Class Imbalance Ruins Metrics: If "LAYING" has 5,000 samples but "WALKING_DOWNSTAIRS" has only 200, accuracy becomes meaningless. EDA verifies balance.
  • Feature Redundancy: 561 features from 6 raw sensor channels means massive overlap. EDA (correlation heatmaps) proves we need dimensionality reduction.
  • Normalization Check: ML algorithms (SVM, KNN, PCA) are distance-based. If one feature is 0.001 and another is 500, the large one dominates. EDA confirms the [-1, 1] range.

Module 2: Unsupervised Learning — K-Means Clustering & DBSCAN

2.1 K-Means Clustering — Theory Deep Dive

What is K-Means?

K-Means is a centroid-based partitioning algorithm that divides N data points into K clusters by minimizing the Within-Cluster Sum of Squares (WCSS), also called Inertia:

Inertia = Σi=1 to K Σx ∈ Ci ||x - μi||²

Where μi is the centroid (mean) of cluster Ci.

The Algorithm (Lloyd's Algorithm):

  1. Initialization: Pick K initial centroids (k-means++ smart seeding picks far-apart points).
  2. Assignment Step: Assign each point to nearest centroid (Euclidean distance).
  3. Update Step: Recompute centroids as mean of assigned points.
  4. Repeat steps 2-3 until centroids stop moving (convergence) or max iterations reached.

Key Hyperparameters:

ParameterOur ValueWhy?
n_clusters6 (varied 2-10 for search)Must test range; 6 matches physical activities
init'k-means++' (default)Smart initialization avoids poor local minima. Random init often fails.
n_init10Run algorithm 10 times with different seeds, keep best (lowest inertia). Critical for stability!
max_iter300 (default)Usually converges in <50 iterations for this dataset.
random_state42Reproducibility. Same seed = same results every run.

2.2 Finding Optimal K — Elbow Method & Silhouette Score

A. Elbow Method (Inertia vs K)

inertias = []
silhouettes = []
K_range = range(2, 11)  # Test K = 2, 3, ..., 10

for k in K_range:
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    labels = km.fit_predict(X_scaled)  # Fit + predict in one call
    inertias.append(km.inertia_)  # WCSS — lower is better

    # Silhouette needs sampling for speed on 7,352 points
    sil = silhouette_score(X_scaled, labels, sample_size=3000, random_state=42)
    silhouettes.append(sil)
Interpreting the Elbow Plot
  • Inertia always decreases as K increases (more centroids = points closer to their centroid).
  • The "elbow" = point of diminishing returns. Going from K=5 to K=6 drops inertia sharply; K=6 to K=7 drops much less.
  • For our data: The elbow is clearly at K=6 — matches the 6 ground-truth activities!

B. Silhouette Score (Cluster Quality Metric)

Mathematical Definition

For a single sample x:

  • a(x) = mean distance to all other points in the same cluster (cohesion).
  • b(x) = mean distance to points in the nearest other cluster (separation).
  • Silhouette(x) = (b(x) - a(x)) / max(a(x), b(x)) ∈ [-1, 1]
  • +1: Well-matched to own cluster, far from others.
  • 0: On the boundary between clusters.
  • -1: Assigned to wrong cluster.

Mean silhouette across all samples = overall clustering quality.

# silhouette_score uses sampling for large datasets
sil = silhouette_score(X_scaled, labels, sample_size=3000, random_state=42)
Viva Q: "Why sample_size=3000? Why not use all 7,352 points?"
Silhouette score computes pairwise distances between all points in a cluster → O(N²) complexity. 7,352² ≈ 54 million distance computations per K value. Sampling 3,000 gives a statistically reliable estimate in seconds instead of minutes. random_state=42 ensures reproducible sampling.

2.3 Cluster Validation Against Ground Truth

Since we have true labels (unsupervised learning doesn't usually!), we can measure how well clusters match reality:

from sklearn.metrics import adjusted_rand_score, normalized_mutual_info_score

ari = adjusted_rand_score(y_train, kmeans_labels)
nmi = normalized_mutual_info_score(y_train, kmeans_labels)
Adjusted Rand Index (ARI)

Compares two partitions (our clusters vs true labels) by counting pairs of samples:

  • RI (Rand Index) = (TP + TN) / (TP + TN + FP + FN) — but high RI can happen by chance.
  • ARI corrects for chance: ARI = (RI - Expected_RI) / (Max_RI - Expected_RI). Range [-1, 1]. 0 = random labeling, 1 = perfect match.
Normalized Mutual Information (NMI)

Information-theoretic measure: how much knowing the cluster reduces uncertainty about the true class.

NMI = 2 * I(C; L) / (H(C) + H(L)) where I = mutual information, H = entropy. Range [0, 1].

Viva Q: "Your ARI is only 0.448. Is that good or bad?"
For K-Means on high-dimensional sensor data without label guidance, ARI ~0.45 is actually quite meaningful! It means the unsupervised clusters capture nearly half the information in the true activity labels. The remaining discrepancy is because K-Means uses spherical Euclidean clusters, but activities like SITTING vs STANDING have similar acceleration magnitudes — they overlap in feature space and need non-linear boundaries (which SVM provides in supervised phase).

2.4 DBSCAN — Density-Based Clustering

How DBSCAN Works (vs K-Means)

K-Means: Assumes spherical clusters of similar size. Fails on arbitrary shapes.
DBSCAN: Groups points in high-density regions separated by low-density regions. Can find arbitrary shapes and identify noise/outliers (label = -1).

Core Concepts:

  • ε (eps): Radius of neighborhood around a point.
  • MinPts (min_samples): Minimum points in ε-neighborhood to form a core point.
  • Core Point: ≥ MinPts neighbors within ε.
  • Border Point: < MinPts neighbors, but within ε of a core point.
  • Noise/Outlier: Neither core nor border (label = -1).

Tuning ε with K-Distance Graph:

# K-distance graph: for each point, find distance to its k-th nearest neighbor
# Sort these distances; the "knee" = optimal eps
from sklearn.neighbors import NearestNeighbors

neighbors = NearestNeighbors(n_neighbors=5)  # 5-NN for min_samples=5
neighbors.fit(X_scaled)
distances, _ = neighbors.kneighbors(X_scaled)
sorted_distances = np.sort(distances[:, -1])  # Distance to 5th nearest neighbor

plt.plot(sorted_distances)  # Look for sharp knee/elbow
Why 5-NN Distance?

We set min_samples=5. The distance to the 5th nearest neighbor represents the local density threshold. If we set ε to this distance, a typical point will have ~5 neighbors. The "knee" in the sorted curve is where density changes sharply — the natural boundary between dense clusters and sparse noise.

DBSCAN Code with Tuned Parameters:

dbscan = DBSCAN(eps=15.0, min_samples=5)
dbscan_labels = dbscan.fit_predict(X_scaled)

n_clusters_ = len(set(dbscan_labels)) - (1 if -1 in dbscan_labels else 0)
n_noise_ = list(dbscan_labels).count(-1)
Viva Q: "How did you decide eps=15.0 exactly?"
From the 5-NN distance graph, we observed a clear knee at approximately distance 15.0. We verified by running DBSCAN with eps in [10, 12, 15, 18, 20] and selecting the value that gave 6 clusters (matching activities) with minimal noise (~5-10%). eps=15.0 gave 6 clusters and ~5% noise points.

Module 3: Dimensionality Reduction — Feature Selection (SelectKBest) & PCA

3.1 Filter-Based Selection: SelectKBest with ANOVA F-Test

What is ANOVA F-Test for Feature Selection?

ANOVA (Analysis of Variance) tests whether the means of a feature differ significantly across classes.

F-Statistic = Between-Class Variance / Within-Class Variance

  • Between-Class Variance: How much class means differ from overall mean.
  • Within-Class Variance: Average spread of feature within each class.
  • High F = Feature values cluster tightly within each class but class centers are far apart = High discriminative power.

SelectKBest ranks all 561 features by F-score and keeps top k.

Code Walkthrough:

from sklearn.feature_selection import SelectKBest, f_classif

k_values = [50, 100, 150, 200, 300, 400]
skb_scores = []

benchmark_clf = RandomForestClassifier(n_estimators=50, random_state=42, n_jobs=-1)

for k in k_values:
    # SelectKBest fits on TRAIN only, then transforms both train & test
    selector = SelectKBest(f_classif, k=k)
    X_sub = selector.fit_transform(X_train_scaled, y_train_enc)

    # Cross-validate on reduced feature set
    score = cross_val_score(benchmark_clf, X_sub, y_train_enc, cv=cv, scoring='accuracy', n_jobs=-1).mean()
    skb_scores.append(score)
Why fit_transform on Train, Only transform on Test?

fit() computes F-scores and learns which k features to keep. transform() applies that same selection. If you fit() on test data, you leak test information (data leakage)! selector.get_support() returns boolean mask of selected features.

3.2 PCA — Principal Component Analysis (Deep Theory)

What is PCA Mathematically?

PCA is an orthogonal linear transformation that projects data onto a new coordinate system where:

  1. First axis (PC1) captures maximum variance.
  2. Second axis (PC2) captures maximum remaining variance orthogonal to PC1.
  3. ...

Mathematically: Eigendecomposition of the Covariance Matrix

Given standardized data X (n × d), covariance Σ = (1/(n-1)) XᵀX. Solve Σv = λv for eigenvectors v (principal components) and eigenvalues λ (variance captured).

Sort eigenvalues λ₁ ≥ λ₂ ≥ ... ≥ λd. PC1 = v₁, PC2 = v₂, etc.

Cumulative variance = Σ λi / Σ λtotal.

PCA Code with 95% Variance Threshold:

# StandardScaler is MANDATORY before PCA
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_train)

# n_components=0.95 means "keep enough PCs to explain 95% of variance"
pca_95 = PCA(n_components=0.95, random_state=42)
X_train_pca = pca_95.fit_transform(X_scaled)

# Key attributes
n_components = pca_95.n_components_  # How many PCs needed for 95%
cumsum_var = np.cumsum(pca_95.explained_variance_ratio_)  # Cumulative variance

# Transform test data using SAME fitted PCA
X_test_pca = pca_95.transform(scaler.transform(X_test))
Explained Variance Ratio — What It Means

pca.explained_variance_ratio_ = [λ₁/Σλ, λ₂/Σλ, ..., λd/Σλ]. Each value is the fraction of total dataset variance captured by that PC.

  • PC1 might explain 35% of all variance.
  • PC2 might explain 18%.
  • First 102 PCs together explain 95% (cumulative sum ≥ 0.95).

This means the remaining 459 components (561 - 102) only contain 5% of the signal — mostly noise!

Scree Plot & Cumulative Variance Plot:

# Scree plot: individual variance per PC
plt.plot(range(1, 51), explained_var[:50], 'bo-')

# Cumulative: how many PCs for X% variance
plt.plot(range(1, 101), cumsum_var[:100], 'ro-')
plt.axhline(0.95, color='red', linestyle='--', label='95% threshold')
Viva Q: "Why n_components=0.95 (float) instead of n_components=102 (int)?"
Using 0.95 tells PCA: "automatically determine how many components are needed to reach 95% cumulative variance." This is more robust than hardcoding 102 because if we change the dataset or preprocessing, the required number of components might change. The float syntax makes the pipeline adaptive.

4.2 Cross-Validation Strategy — Stratified K-Fold

from sklearn.model_selection import StratifiedKFold

# StratifiedKFold preserves class % in each fold
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
Why Stratified? Why 5 Folds? Why Shuffle?
  • Stratified: Each fold has exactly same % of each of the 6 classes. Without stratification, a fold might have 0 samples of WALKING_DOWNSTAIRS → model never sees it during training for that fold.
  • 5 Folds: Standard tradeoff. More folds (e.g., 10) = more training data per fold (90% vs 80%) but 2× compute time. 5 is standard.
  • Shuffle=True: Data is sorted by subject/activity. Without shuffle, fold 1 might be all "LAYING" samples. random_state=42 ensures reproducible splits.

4.3 Cross-Validation Scoring — Multiple Metrics

# cross_val_score returns array of scores (one per fold)
cv_acc = cross_val_score(model, X_train_scaled, y_train_enc, cv=cv, scoring='accuracy', n_jobs=-1)

# Mean ± Std across 5 folds

Macro vs Micro vs Weighted Averaging
  • Macro: Compute metric per class, then average. Treats all classes equally. Best for balanced classes.
  • Micro: Aggregate TP, FP, FN globally, then compute. Favors majority classes.
  • Weighted: Macro but weighted by class support (sample count).

We use Macro because our classes are roughly balanced and we care equally about all 6 activities.

Module 5: Ensemble Learning — Hard Voting vs Soft Voting

5.1 Why Ensembles Work — Bias-Variance Decomposition

Expected Error = Bias² + Variance + Irreducible Error
  • Bias: Error from wrong assumptions (e.g., linear model on curved boundary). High bias = underfitting.
  • Variance: Error from sensitivity to training data fluctuations. High variance = overfitting.
  • Ensembles reduce VARIANCE by averaging diverse models. If models make independent errors, averaging cancels them out.

Diversity is key! Models must make different errors on different samples. That's why we combine SVM (kernel), Random Forest (trees), KNN (instance-based), AdaBoost (boosting).

5.2 Hard Voting vs Soft Voting — Mathematical Difference

Hard Voting (Majority Rule):

Each model outputs a single class label. The ensemble predicts the class with the most votes.

ŷ = mode { C₁(x), C₂(x), C₃(x), C₄(x) }

Soft Voting (Probability Averaging):

Each model outputs class probabilities (requires probability=True for SVM). The ensemble averages probabilities and takes argmax.

ŷ = argmaxc Σi=1..M Pi(y = c | x)

Why Soft Voting Usually Wins

Hard voting treats a 51% confident prediction equal to a 99% confident one. Soft voting respects confidence:

  • Sample A: SVM 95% "Walking", RF 52% "Standing", KNN 51% "Standing" → Soft picks "Walking" (correct!). Hard picks "Standing" (2 vs 1).
  • Soft voting uses the full posterior distribution which contains more information than just the argmax.

SVC(probability=True) enables predict_proba() by fitting an additional calibration model (Platt scaling: logistic regression on SVM decision scores) via 5-fold CV internally. Without it, soft_voting fails because SVM cannot output probabilities. Hard voting doesn't need it. The extra computation is worth it for the accuracy gain.

Module 7: Professor Viva — Anticipated Questions & Deep Answers

Q1: "Why did you use StandardScaler and not MinMaxScaler? When would you use each?"
StandardScaler (Z-score): x' = (x - μ) / σ. Centers data at 0, unit variance.
Use when: Algorithm uses distance (KNN, SVM), gradient descent (Linear/Logistic Regression, Neural Nets), or variance-based methods (PCA).

MinMaxScaler: x' = (x - min) / (max - min). Bounds to [0, 1].
Use when: Algorithm needs bounded input (e.g., neural nets with sigmoid/tanh, image pixels), or when you want to preserve exact zero values in sparse data.

Our Case: PCA, SVM (RBF uses Euclidean distance), KNN, and Logistic Regression all need StandardScaler. Our data is already in [-1, 1] from UCI preprocessing, but StandardScaler centers it at 0 which PCA requires.
Q2: "Explain the Kernel Trick in SVM RBF. Why not just use Linear SVM?"
Linear SVM: Finds hyperplane w·x + b = 0. Only works if classes are linearly separable. In 561-D sensor space, walking vs sitting boundaries are CURVED, not flat planes.

Kernel Trick: Instead of explicitly mapping x → φ(x) in high-D space (expensive!), we compute dot products in that space via kernel function K(x, x') = φ(x)·φ(x').

RBF Kernel: K(x, x') = exp(-γ ||x - x'||²). This implicitly maps to INFINITE-dimensional space where a linear hyperplane corresponds to a NON-LINEAR boundary in original space. γ controls "reach" of each support vector.

Why RBF worked best: Human motion manifolds are locally smooth but globally complex. RBF's infinite-dimensional flexibility captures this better than polynomial (fixed degree) or linear.
Q3: "What is Gini Impurity vs Entropy in Decision Trees? Why Gini?"
Gini Impurity: G = 1 - Σ pc². Probability of misclassifying a randomly chosen sample if labeled by class distribution in node.
Entropy: H = -Σ pc log₂ pc. Information theory measure of uncertainty.

Both lead to similar trees. Gini is slightly faster to compute (no log). Default in scikit-learn. For our 6-class problem, both work; we used default criterion='gini'.
Q4: "Why does Weighted KNN beat standard KNN? Explain the math."
Standard KNN (uniform): Each of k neighbors gets 1 vote. Prediction = majority class among k neighbors. All neighbors weighted equally regardless of distance.

Weighted KNN (distance): Weight wᵢ = 1 / d(x, xᵢ) (or 1/d²). Closer neighbors contribute more.

Why it helps in our data: Sensor noise creates outliers. In standard KNN, a noisy neighbor at distance 10 counts the same as a clean neighbor at distance 0.1. Weighted KNN suppresses the noisy neighbor's influence by factor of 100×. Result: smoother decision boundaries, higher accuracy (92.4% vs 91.5% for k=5).
Q5: "Explain Bagging vs Boosting. Why does Random Forest (Bagging) work better than AdaBoost (Boosting) here?"
Bagging (Bootstrap Aggregating - Random Forest): Trains N models in PARALLEL on different bootstrap samples (sampling with replacement). Each tree sees different data + different feature subset (max_features). Reduces VARIANCE by averaging decorrelated trees. Very robust to noise/outliers.

Boosting (AdaBoost): Trains models SEQUENTIALLY. Each new model focuses on samples PREVIOUS models got wrong (reweights them). Reduces BIAS but INCREASES sensitivity to outliers/noise. If a noisy sample is misclassified, AdaBoost keeps increasing its weight, forcing later models to overfit it.

Why RF (93.8%) > AdaBoost (53.4%): Our sensor data has noise. AdaBoost obsessively chases noisy outliers, degrading performance. RF's averaging is inherently robust.
Q6: "What is the curse of dimensionality? How did PCA solve it for KNN?"
Curse of Dimensionality: As dimensions increase:
1. Volume of space grows exponentially → data becomes extremely sparse.
2. All pairwise distances converge → nearest and farthest neighbor become equidistant.
3. KNN relies on "nearest" being meaningful. In 561-D, distance concentration makes "nearest" almost random.

PCA Solution: Projects data onto 102 orthogonal components capturing 95% variance. In this lower-dimensional manifold:
1. Noise dimensions (with near-zero variance) are discarded.
2. Remaining dimensions have meaningful distance relationships.
3. KNN distances become discriminative again.
Q7: "Your test accuracy is 96.84%. How do you know this isn't overfitting or data leakage?"
No Leakage Evidence:
1. Subject-wise Split: Train volunteers (1-21) ≠ Test volunteers (22-30). Model never sees test person's gait pattern during training.
2. Strict Preprocessing: StandardScaler, SelectKBest, PCA all fitted ONLY on training data. Test data only transformed.
3. CV Strategy: Stratified 5-Fold on training data only. Test set untouched until final evaluation.
4. CV-Test Gap: CV accuracy (96.5%) ≈ Test accuracy (96.8%). Small positive gap is normal (full training data > 80% CV folds). Large gap (>2-3%) would indicate overfitting/leakage.
Q8: "Why did you choose C=10.0 for SVM? What does C control?"
C (Regularization Parameter): Controls the tradeoff between:
- Low C: Wider margin, more misclassifications allowed (high bias, low variance).
- High C: Narrower margin, fewer training errors (low bias, high variance).

C=10.0 was selected after testing [0.1, 1, 10, 100] via cross-validation. C=10 gave best CV score. C=100 started overfitting (CV dropped). C=1.0 underfit (margin too wide).
Q9: "Explain the difference between cross_val_score and cross_val_predict."
cross_val_score: Returns array of scores (one per fold). Used for model selection and hyperparameter tuning. Does not return predictions.
cross_val_predict: Returns predictions for EVERY sample in the dataset, where each sample is predicted by the model that did NOT see it during training (i.e., the fold where it was in validation set). Useful for getting out-of-fold predictions for stacking, plotting confusion matrices per fold, or computing per-sample metrics.

We used cross_val_score for all model comparisons because it's faster (no need to store predictions) and directly gives the metrics we need.
Q10: "What is n_jobs=-1? Why use it? Any downsides?"
n_jobs=-1 means "use all available CPU cores". scikit-learn uses joblib for parallelization.

Used in: RandomForest (n_jobs=-1 builds trees in parallel), cross_val_score (n_jobs=-1 runs folds in parallel), GridSearchCV, etc.

Downsides: (1) Memory usage multiplies (each process copies data). On small RAM, can cause OOM. (2) Slight overhead for small tasks. (3) Not thread-safe with some libraries.

We used it because 5-fold CV × 11 models × 7,352 samples is computationally heavy. Parallelization cut runtime from ~10 minutes to ~2 minutes.
Q11: "Why did you use LabelEncoder instead of OneHotEncoder for the target?"
LabelEncoder maps string labels → integers (0, 1, 2, 3, 4, 5). Used for target variable (y) in classification. Classifiers like SVM, RF, KNN natively accept integer labels.

OneHotEncoder creates binary columns for each class. Used for categorical FEATURES (X), not targets. If we one-hot encoded the target, we'd get 6 binary columns — that's for multi-label classification or neural networks with softmax output, not standard scikit-learn classifiers.
Q12: "Your confusion matrix shows SITTING and STANDING are most confused. Why? How to fix?"
Reason: Both are static postures. The smartphone on waist experiences nearly identical gravity vector (1g downward) and near-zero dynamic acceleration. Only subtle differences: hip angle, pressure distribution, micro-movements. In 561-D feature space, their centroids are extremely close.

Fixes: (1) Add more sensors (e.g., thigh-worn accelerometer for thigh angle). (2) Use temporal models (LSTM/TCN) on raw time series — posture transitions reveal differences. (3) Engineer features from gyroscope (body orientation relative to gravity). (4) Ensemble already helps (Soft Voting uses probability nuance).
